End-to-End DevSecOps Pipeline
Problem: Security scanning was a manual, post-release step. Vulnerabilities were caught in production.

EKS Autoscaling Platform — KEDA + Karpenter
Problem: Fixed node pools caused 3× over-provisioning during off-peak and job failures during burst.
Replaced Cluster Autoscaler with Karpenter using provisioner policies that consolidate nodes and right-size instance types based on workload shape. Layered KEDA on top to scale deployments directly from Kafka consumer-lag and SQS queue depth metrics, decoupling application scaling from node scaling. Spot instance support with interruption handling reduced compute costs significantly.

Architecture

How I build systems

Two disciplines, one philosophy: everything is code, everything is observable, everything is secure by default.

🔐 DevSecOps Pipeline Architecture
  1. 1
    Code — Shift Left Security
    Pre-commit hooks (Detect-secrets, Hadolint). SAST via Semgrep on every PR. Gated on zero critical findings.
  2. 2
    Build — Immutable Artifacts
    Docker BuildKit multi-stage builds. Container image signed with Cosign (Sigstore). SBOM generated and stored in OCI registry.
  3. 3
    Test — Policy Enforcement
    OWASP Dependency-Check, Trivy image scan, OPA Conftest for Kubernetes manifests. Hard-fail on HIGH+ CVEs.
  4. 4
    Deploy — GitOps + Admission Control
    ArgoCD syncs from Git. Gatekeeper enforces runtime policies (no :latest tags, resource limits required, PodSecurityStandards).
  5. 5
    Operate — Continuous Verification
    Falco runtime threat detection. Continuous compliance scanning with Prowler (AWS) / Checkov. SLO alerting via Sloth.
🤖 MLOps Platform Architecture
  1. 1
    Data — Feature Store
    Offline store (Hive/S3) + online store (Redis). Feast manages feature definitions and point-in-time joins. No training/serving skew.
  2. 2
    Train — Kubernetes-Native Jobs
    Kubeflow Pipelines orchestrates steps. Training Jobs use GPU node selectors and toleration policies. MLflow tracks params, metrics, artifacts.
  3. 3
    Validate — Automated Quality Gates
    Model performance compared to production baseline. Fairness and bias checks. Signed model artifact promoted to registry only if gates pass.
  4. 4
    Serve — Canary + Traffic Splitting
    Istio routes 10% of traffic to new model. Prometheus tracks prediction distribution. Auto-rollback on drift or latency SLO breach.
  5. 5
    Monitor — Data & Model Drift
    Evidently for statistical drift detection. Kafka streams feed real-time predictions into a monitoring topic. Grafana dashboards per model.
